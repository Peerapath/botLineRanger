# เครื่องมือต่ออายุโทเค็นไฟล์บัญชีแบบไม่ใช้เกม (headless relogin batch)

วันที่: 2026-09-14

## เป้าหมาย

ต่ออายุ `_ENC_LF_AC_KEY` ในไฟล์บัญชี GUEST (`_LINE_COCOS_PREF_KEY.xml`) ทั้งโฟลเดอร์
โดยไม่ต้องเปิดเกมหรือใช้ emulator เลย แล้วเขียนโทเค็นใหม่ทับลงไฟล์เดิม
เป้าแรกคือ `bot/input/15-3` (21,984 ไฟล์) ซึ่งตอนนี้โทเค็นในไฟล์ตายหมดแล้ว (ยิง `/home` ได้ 401)

## ที่มา (ทดสอบกับเซิร์ฟเวอร์จริงแล้ว 2026-09-14)

เซิร์ฟเวอร์ระบุตัวผู้เล่นจาก LF_AC เก่าที่เก็บในไฟล์ ไม่ใช่จากเครื่อง:

```
GET https://rangers-api.line-apps.com/v12.3/login
Cookie: cc=<userToken ของ guest ไลน์เกมที่ใช้ได้>; udid=<_DEVICE_UUID_KEY>; guestCookie=<LF_AC เก่าเต็ม 280 ตัว>;
-> 200, result.rsn / level / isNew=False, Set-Cookie: LF_AC=<โทเค็นใหม่>
```

- ใช้ได้ 12/12 ไฟล์ รวมไฟล์เก่าสุด ธ.ค. 2025
- ไม่มี `cc` / `cc` มั่ว / ไม่มี `guestCookie` = 401
- `cc` ตัวเดียวใช้ซ้ำกับหลายบัญชีได้
- เซิร์ฟเวอร์ไม่ตรวจ `udid` แต่ต้องใช้ udid เดิมเป็นกุญแจเข้ารหัส ไม่อย่างนั้นเกมจะถอดไม่ออก
- ไฟล์ต้นฉบับยังล็อกอินได้หลังต่ออายุแล้ว และโทเค็นจากการล็อกอินคนละรอบใช้ได้พร้อมกัน

## ขอบเขต

ทำ:
- CLI ใหม่ `tools/relogin.py` ต่ออายุทุกไฟล์ `.xml` ในโฟลเดอร์ที่ระบุ (รวมโฟลเดอร์ย่อย)
- เขียนทับไฟล์เดิม โดยสำรองต้นฉบับไว้ก่อน
- รันต่อจากเดิมได้ และทำหลาย thread พร้อมกัน

ไม่ทำ:
- เปลี่ยนชื่อไฟล์, ดึง ruby/ตั๋ว, เชื่อมเข้าบอท, สร้างบัญชีใหม่จากศูนย์ (บัญชีใหม่ไม่มี `guestCookie` จึงทำไม่ได้)

## การใช้งาน

```
python tools/relogin.py <โฟลเดอร์> [--workers 4] [--limit N] [--force]
```

- `--workers` จำนวน thread (ค่าเริ่มต้น 4)
- `--limit N` ทำแค่ N ไฟล์แรกที่ยังไม่สำเร็จ (เรียงตาม path) ไว้ลองก่อน
- `--force` ทำซ้ำแม้ไฟล์เคยสำเร็จแล้ว

## ส่วนประกอบ

`tools/relogin.py` ใช้โค้ดที่มีอยู่ ไม่เขียนซ้ำ:

| ต้องการ | ใช้ของเดิม |
|---|---|
| สร้าง guest เพื่อได้ `cc` | `new_account.register_guest(device_id)` → `["userToken"]` |
| ยิง HTTP + อ่าน Set-Cookie | `new_account._do`, `new_account._cookie_value` |
| ถอดรหัส LF_AC | `device_session.decrypt_lfac` |
| เข้ารหัส LF_AC | `account_file.encrypt_lfac`, `account_file._wrapped` |
| เวอร์ชัน API | `rangers_api.API` (`/v12.3`), `rangers_api.CLIENT_VERSION` (`12.3.0`) |

ฟังก์ชันหลักในไฟล์ใหม่:

- `read_account(path) -> dict` อ่าน udid, enc, nation, language และข้อความ XML ดิบ
- `login(cc, udid, guest_cookie, nation, language) -> (status, result, lf_ac)`
  ยิง `/v12.3/login` ด้วย header ชุดเดียวกับ `new_account.game_login` แต่ใช้
  App-Version `LGRGS/<CLIENT_VERSION>;android/12` และ `Nation-Code` ของไฟล์
  (`new_account.py` ยังเป็น 12.2.4 จึงไม่เรียก `game_login` ตรง ๆ)
- `replace_enc(xml_text, udid, lf_ac) -> str` แทนที่ **เฉพาะค่า** ใน
  `<string name="_ENC_LF_AC_KEY">…</string>` ด้วย blob ใหม่ในรูปแบบ `_wrapped`
  ส่วนอื่นของไฟล์คงเดิมทุกไบต์ (15,605 ไฟล์ใน 15-3 ขึ้นบรรทัดแบบ CRLF ขนาด 792 ไบต์
  ถ้าสร้างไฟล์ใหม่ทั้งไฟล์ด้วย `build_pref_xml` จะเปลี่ยนไปเป็น 784)
- `CcPool` เก็บ `cc` ตัวปัจจุบันที่ทุก thread ใช้ร่วมกัน มี lock และจำเวลาที่ `cc` ตัวนี้
  ล็อกอินสำเร็จครั้งล่าสุด
  - `renew(old_cc)` สร้างใหม่แค่ครั้งเดียว ถ้าหลาย thread ขอพร้อมกันด้วย `cc` ตัวเดิม
  - `is_proven()` = `cc` ตัวนี้เพิ่งล็อกอินสำเร็จภายใน 60 วินาที ถ้าใช่ แปลว่า 401
    เป็นปัญหาของไฟล์นั้นเอง (เช่นบัญชีโดนแบน) ไม่ต้องสร้าง `cc` ใหม่ กันการสร้าง guest
    ทีละบัญชีต่อทุกไฟล์ที่เสีย
- `process(path)` ทำงานของไฟล์เดียวตามลำดับด้านล่าง แล้วคืนผลหนึ่งแถว

## ลำดับการทำงานต่อไฟล์

1. `read_account` ถ้าอ่านไม่ได้ หรือไม่มี `_DEVICE_UUID_KEY` / `_ENC_LF_AC_KEY` → สถานะ `bad_file`
2. ถอดรหัส LF_AC เก่า ถ้าถอดไม่ได้ → `bad_file`
3. `login` ด้วย `cc` ปัจจุบัน
   - 200 และมี LF_AC ใหม่ → ไปข้อ 4
   - 401 และ `cc` ยัง `is_proven()` → `rejected` ทันที
   - 401 และ `cc` ยังไม่เคยสำเร็จหรือนานเกิน 60 วินาที → `CcPool.renew` แล้วลองไฟล์นี้
     อีกครั้ง ถ้ายัง 401 → `rejected`
   - error เครือข่าย / 429 / 5xx → รอแบบเพิ่มเวลา (2, 4, 8 วินาที) สูงสุด 3 ครั้ง
     ถ้ายังไม่ได้ → `error`
4. สำรอง: ถ้ายังไม่มี `<โฟลเดอร์>_backup/<path เดิม>` ให้คัดลอกต้นฉบับไปก่อน
   (ไม่ทับไฟล์สำรองที่มีอยู่แล้ว ต้นฉบับแรกสุดจึงอยู่ตลอด)
5. `replace_enc` แล้วเขียนลงไฟล์ชั่วคราวในโฟลเดอร์เดียวกัน ตามด้วย `os.replace`
   ทับไฟล์เดิม ไฟล์จึงไม่ค้างครึ่ง ๆ ถ้าโปรแกรมหยุดกลางคัน
6. ตรวจทันที: อ่านไฟล์ที่เขียนกลับมาถอดรหัส ต้องได้ LF_AC ใหม่ตรงกัน ไม่ตรง → `error`
   และเขียนข้อความ XML เดิมที่อ่านไว้ในข้อ 1 กลับลงไป (ไม่ใช้ไฟล์สำรอง เพราะไฟล์สำรอง
   อาจเป็นต้นฉบับจากรอบก่อนหน้า)
7. สถานะ `ok` พร้อม rsn และ level จากผลล็อกอิน

## การหยุดอัตโนมัติ

- **401 ติดกัน 10 ไฟล์** (นับทุกไฟล์ที่จบด้วย `rejected` ตามลำดับที่เสร็จ
  ไฟล์ `ok` คั่นเมื่อไรเริ่มนับใหม่) → หยุดทั้งหมด พิมพ์ว่าน่าจะเป็นช่วงเซิร์ฟเวอร์
  ปิดปรับปรุง (ช่วงนั้นทุกคำขอได้ 401) ไฟล์ที่ยังไม่ทำจะรันต่อได้ภายหลัง
- **`error` ติดกัน 60 ไฟล์ → หยุดทั้งหมด** (ระบุ ERROR_STOP) การรับมือ error ชั่วคราว
  ทำที่ระดับคำขอแทน: `login()` retry เองพร้อม backoff (2/4/8 วินาที) เมื่อเจอ
  network error / 429 / 5xx ก่อนจะยอมแพ้เป็น 1 error ดังนั้นไม่ต้องมีการ "พัก" ทั้ง batch
  แยกต่างหาก — error ที่เหลือหลัง retry คือของจริง และเมื่อสะสมติดกันมากพอก็หยุด (รันต่อได้ภายหลัง)
- Ctrl+C → หยุดรับงานใหม่ รอ thread ที่ทำอยู่เสร็จ แล้วปิดไฟล์บันทึกให้เรียบร้อย

## บันทึกผลและการรันต่อ

- ไฟล์บันทึก `<โฟลเดอร์>.relogin.csv` (อยู่ข้างโฟลเดอร์ เช่น `bot/input/15-3.relogin.csv`)
  คอลัมน์ `path,status,rsn,level,time` โดย path เป็น path จากโฟลเดอร์ที่ระบุ
- เขียนต่อท้ายทีละแถวทันทีที่ไฟล์เสร็จ (ผ่าน lock เดียว) ไม่รอจบทั้งรอบ
- ตอนเริ่ม อ่านไฟล์บันทึกเดิม ไฟล์ที่เคยได้ `ok` จะถูกข้าม เว้นแต่ใส่ `--force`
  สถานะอื่น (`rejected`, `error`, `bad_file`) จะถูกลองใหม่
- พิมพ์ความคืบหน้าทุก 100 ไฟล์: ทำไปกี่ไฟล์จากทั้งหมด, ok / rejected / error / bad_file,
  ความเร็วต่อนาที และเวลาที่เหลือโดยประมาณ
- จบรอบพิมพ์สรุปยอดรวม

## ความปลอดภัยของข้อมูล

- ไฟล์บันทึกไม่มีโทเค็น มีแค่ path, สถานะ, rsn, level
- ห้ามพิมพ์ LF_AC หรือ `cc` ออกหน้าจอ
- เพิ่มใน `.gitignore`: `bot/input/`, `*_backup/`, `*.relogin.csv`
  (ไฟล์บัญชีและไฟล์สำรองมีโทเค็นที่ใช้ล็อกอินบัญชีได้)

## การทดสอบ

แบบไม่ต่อเน็ต (สคริปต์ทดสอบใน `tools/`):
- `replace_enc` แล้วถอดรหัสกลับได้ LF_AC ตรงกัน
- ส่วนอื่นนอกค่า `_ENC_LF_AC_KEY` เหมือนต้นฉบับทุกไบต์ ทั้งไฟล์แบบ LF (784) และ CRLF (792)
- `USER_NATION_CODE` และ `LANGUAGE_TYPE_SETTING_KEY` ไม่เปลี่ยน

ต่อเซิร์ฟเวอร์จริง:
1. คัดลอกไฟล์จาก `bot/input/15-3` มา 3 ไฟล์ไว้ในโฟลเดอร์ทดสอบใน scratchpad
2. รัน `relogin.py <โฟลเดอร์ทดสอบ> --limit 3`
3. ยิง `/home` ด้วยโทเค็นที่ถอดจากไฟล์ที่เขียนใหม่ ต้องได้ 200 และ rsn ตรงกับผลในไฟล์บันทึก
4. เช็กว่ามีไฟล์สำรองครบ 3 ไฟล์และเหมือนต้นฉบับ
5. รันซ้ำ ต้องข้ามทั้ง 3 ไฟล์
6. จากนั้นลองกับ `bot/input/15-3` จริงด้วย `--limit 20` ก่อนปล่อยทั้งโฟลเดอร์

## ความเสี่ยงที่รู้อยู่

- ทุกครั้งที่สร้าง `cc` ใหม่ = สร้างบัญชี guest ไลน์เกม 1 บัญชี (เกมก็ทำแบบนี้ทุกครั้งที่ import ไฟล์)
  การใช้ `cc` ร่วมกันทำให้ทั้งรอบสร้างแค่ไม่กี่บัญชี
- ยังไม่รู้อายุของ `cc` ถ้าหมดอายุกลางรอบ กลไก `renew` ตอนเจอ 401 จะจัดการเอง
- ยังไม่รู้เพดาน rate limit ของ `/login` จึงเริ่มที่ 4 thread และมีตัวหยุด/พักอัตโนมัติ
- ยังไม่รู้อายุของโทเค็นใหม่ (เท่าที่วัดได้คือเกิน 14 ชม.) แต่ถ้าหมดอายุก็รันเครื่องมือนี้ซ้ำได้
